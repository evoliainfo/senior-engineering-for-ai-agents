# v1.3.0-beta

**Status:** Public beta  
**Date:** 2026-08-19

This is the first public beta of **Senior Engineering for AI Coding Agents**.

## What this beta is for

The goal is to test whether SEF can consistently make Codex and Claude Code work through a governed software-engineering lifecycle instead of treating a successful code edit or green build as sufficient proof of completion.

The beta is intended for controlled real-project testing.

## User experience

The normal workflow is deliberately simple:

1. put `sef.py` at the root of a new or existing project;
2. open that project in Codex or Claude Code;
3. describe the software you want to build;
4. let the coding agent operate SEF.

The user is not expected to know SEF commands or to enumerate every professional engineering requirement.

## Project lifecycle

SEF frames work through:

```text
PROJECT DESCRIPTION
→ DISCOVERY
→ PROJECT ENGINEERING BASELINE
→ REQUIREMENTS + INFERRED PROFESSIONAL REQUIREMENTS
→ ARCHITECTURE / DATA / SECURITY / QUALITY STRATEGY
→ DYNAMIC TASK PLANNING
→ IMPLEMENTATION
→ ACTUAL-DIFF REASSESSMENT
→ VERIFICATION / EVIDENCE
→ RELEASE GATE
→ OBSERVE / MAINTAIN
```

## Multi-agent support

### Codex

### Claude Code

SEF installs and preserves project instructions through `CLAUDE.md`.

## Risk and evidence

SEF classifies work from lightweight R0 changes through high-risk R3/R4 changes. Risk classification can be escalated by the actual implementation diff.

Evidence distinguishes:

`PASS`, `FAIL`, `NOT_RUN`, `UNAVAILABLE`, `INCONCLUSIVE`, `FLAKY`, `N/A`, `WAIVED`, and `BLOCKED`.

The goal is to prevent unsupported "DONE" claims.

## Python runtime

The beta runtime requires Python 3.

An agent should first detect an existing compatible runtime (`python3`, `python`, or Windows `py -3`). If Python is absent, the agent must not silently install system software or bypass sandbox/permission controls. Installation should use a trusted mechanism and normal user/agent approvals.

## Integrity

Verify the distributed runtime against `SHA256SUMS` before relying on it in a sensitive environment.

## Known boundaries

This beta does not claim:

- AI-model infallibility;
- automatic legal or regulatory compliance;
- replacement of sandboxing, CI, protected branches or human approval;
- universal stack-specific expertise without consulting the actual repository and authoritative platform/framework documentation.

## What feedback matters most

Please report reproducible cases where SEF:

- misses an important engineering requirement;
- routes the wrong risk level;
- loads the wrong playbook;
- creates excessive friction for a low-risk task;
- fails to detect a changed implementation scope;
- allows an agent to claim completion without adequate evidence;
- asks the user a technical question that SEF should have inferred itself;
- makes unsafe assumptions about data, tenancy, criticality or production.

Use the repository issue template and include the original user request, relevant project context, SEF output, actual agent behavior and expected behavior.
